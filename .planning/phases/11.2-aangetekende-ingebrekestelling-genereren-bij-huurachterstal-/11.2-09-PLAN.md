Deployment facts (project memory, confirmed in 11-07-SUMMARY.md):
- Production host m1, checkout at /var/www/rentular.com, branch main. Shared box with about 40 unrelated databases: every statement is scoped to the database `rentular`.
- The API runs from source with tsx under PM2 (port 4100); the web app needs a build (next build with the .env sourced so NEXT_PUBLIC_API_URL is inlined), port 3100.
- Restart only through the ecosystem file: pm2 restart /var/www/rentular.com/ecosystem.config.cjs --update-env. A plain pm2 restart rentular-api reuses a stale saved environment.
- drizzle-kit push throws TypeError reading 'checkConstraint' on this MariaDB; db:generate replays a stale baseline. Neither is used.

- The DDL is additive and idempotent, so applying it while the old code is still running is safe.

Sample PDFs without production data: pnpm --filter=@rentular/api exec tsx src/scripts/formalNoticeSample.ts <outDir> writes formal-notice-{nl,fr,de,en}-{3,12}.pdf (plan 11.2-04).

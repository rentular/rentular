# Phase 11.2 Plan 04: A4 letter renderer and a real reminder attachment Summary

**One pdfkit module turns a LetterDocument into a paginated A4 PDF with embedded Liberation Sans, and the final reminder stops attaching plain text that the queue could not deliver anyway.**

## Performance

- **Duration:** 18 min
- **Started:** 2026-11-19T00:52:00Z
- **Completed:** 2026-11-19T01:10:00Z
- **Tasks:** 2 (both TDD, RED committed before GREEN)
- **Files created:** 3, modified: 5

## Accomplishments

**Task 1: `lib/pdfLetter.ts`.** `renderLetterPdf(document, opts?)` draws the postal blocks in the Belgian envelope window, the place and date, the subject and then the paragraph, table, amounts and signature blocks. A4 at 595.28 by 841.89 points, margins 57 top and bottom, 71 left and right. Both committed TTFs are registered and the body font is selected before anything is drawn, so the built-in Helvetica never reaches the file. Every string goes through one draw helper that normalises to NFC, so a decomposed accent cannot slip in from a call site. Tables repeat their header after a page break, a signature never stands alone (the paragraph above it is measured first and the break goes before it), and page numbers appear only from two pages up. `resolveFontDir()` tries an absolute `FORMAL_NOTICE_FONT_DIR`, then `../../assets/fonts`, `../assets/fonts` and `./assets/fonts` relative to the module, caches the hit, and throws naming every path tried.

**Task 1: the sample script, now also the ops check.** `formalNoticeSample.ts` writes eight letters (nl, fr, de, en, three and twelve arrears months) and asserts what it wrote: non-zero bytes and a `%PDF-` header per file, an embedded font program, no Helvetica fallback, and at least one glyph outside Latin-1 present in the document's ToUnicode CMap. It prints every path it writes, the pdfkit version read off the installed package, and one `PASS:` or `FAIL:` line, and exits non-zero on failure. No database, no network, no `.env`.

**Task 2: the final reminder.** `buildLatePaymentOverviewDocument` is the overview as a `LetterDocument` in four languages, with the interest row only when the owner enabled interest, the fee row only when the lease charges one, the soft-enforcement waiver sentence only when both apply, and a single bold total equal to rent plus interest plus fee. `generateLatePaymentPdf` draws it. `buildFinalReminderAttachment` hands it over as a base64 string with `encoding: "base64"`, which is the actual production fix: the old `Buffer` came back out of Redis as `{ type: "Buffer", data: [...] }` and made nodemailer throw in the worker, so no final reminder was arriving at all. The plain-text body and its TODO are gone, and `emailQueueWorker.ts` was not touched.

## Deviations from Plan

### 1. [User requirement, added at launch] The sample script is also a self-asserting ops smoke check

- **Found during:** Task 1, from the requirement attached to this run.
- **Planned:** a developer tool that renders eight sample PDFs for the printed check in plan 11.2-09 and prints the paths.
- **Actual:** the same script, same task, plus assertions and an exit code. It checks non-zero bytes and a `%PDF-` header for each file, that a font program is embedded, that no Helvetica fallback happened, and that a glyph outside Latin-1 is present in the ToUnicode CMap. It prints the pdfkit version read off the installed package (resolved by walking up from `require.resolve("pdfkit")`, because pdfkit's `exports` map hides `./package.json`) and ends on a single `PASS:` or `FAIL:` line. Exit 0 on pass, 1 on failure, runnable with no database, no network and no `.env`.
- **Why:** pdfkit is a caret range so Dependabot keeps it current (plan 11.2-01, deviation 1). A renderer that silently stops embedding glyphs after a bump still writes files that look fine in a listing, so the user asked for something an ops person can run after an update.
- **Cost if wrong:** a false PASS would let a broken bump through. The failure path was exercised for real (fonts moved aside gives `FAIL` and exit 1) rather than assumed, and the glyph assertion reads the CMap instead of trusting the header.
- **Files:** `apps/api/src/scripts/formalNoticeSample.ts`. **Commit:** `eede275`.
- **Not done here:** the ops runbook document. The orchestrator writes that.

### 2. [Stronger than planned] The glyph check reads the ToUnicode CMap

- **Found during:** Task 1, while deciding how to reuse plan 11.2-01's smoke approach.
- **Planned:** reuse the approach the 11.2-01 smoke test used.
- **Actual:** the uncompressed render is searched for the CMap entries of three code points outside Latin-1, verified first against real pdfkit output (it writes lowercase four-digit hex inside a `beginbfrange` block).
- **Why:** 11.2-01's check rendered the names and asserted the header, which is one step better than calling `end()` but still cannot distinguish an embedded subset from a corrupted one. The CMap entry only exists when fontkit actually subset that code point out of the TTF.
- **Cost if wrong:** if a future pdfkit wrote the CMap differently the script would report FAIL on a healthy renderer, which is the safe direction for a release gate. The same three code points are also covered independently by the `pdftotext` test in `pdfLetter.test.ts`.
- **Files:** `apps/api/src/scripts/formalNoticeSample.ts`. **Commit:** `eede275`.

### 3. [Scope choice] Arrears totals for the sixty-month and twelve-month cases are computed locally, not added to the plan 11.2-03 fixture

- **Found during:** Task 1, writing the page-break test.
- **Planned:** nothing explicit; the obvious route was a new fixture helper.
- **Actual:** both the test and the sample script call `computeFormalNoticeTotals(..., letterInterest)` through a small local helper. `apps/api/src/services/__tests__/fixtures/arrearsLease.ts` was not modified.
- **Why:** the fixture belongs to plan 11.2-03 and plan 11.2-05 reads it too. A three-line local helper is cheaper than changing a shared fixture under a parallel wave.
- **Cost if wrong:** two copies of a three-line helper. If a third caller appears it should move into the fixture.
- **Files:** `apps/api/src/lib/__tests__/pdfLetter.test.ts`, `apps/api/src/scripts/formalNoticeSample.ts`. **Commit:** `eede275`.

## Assumption Drift (advisory)

**1. The font path is anchored on the renderer module, not on the caller**

- **Found during:** Task 1.
- **Planned:** the behaviour list reads "`resolveFontDir()` returns a directory that contains both TTFs when called from the test's module location".
- **Actual:** resolution is anchored on `pdfLetter.ts`'s own `import.meta.url`, so the answer is the same no matter who calls it. The test asserts the result, not the caller's location.
- **Why:** anchoring on the caller would make the result depend on which module happened to call, which is the exact fragility Pitfall 7 is about.
- **Cost if wrong:** none observed. A future caller in a different directory does not need its own candidate list.

**2. `import.meta.url` works under `tsx` even though `apps/api` is CommonJS**

- **Found during:** Task 1, probing before writing the resolver.
- **Planned:** the plan treats `import.meta.url` as available in production because `bootstrap.ts` already uses it.
- **Actual:** confirmed by running a throwaway script under `tsx`: `apps/api/package.json` has no `"type": "module"`, but tsx's transform still provides `import.meta.url` and the path resolved correctly. A file outside the package (in `/tmp`) fails with "Top-level await is currently not supported with the cjs output format", which is a property of the location, not of the resolver.
- **Why worth recording:** anyone moving this script out of `apps/api/src` will hit the CJS transform, and the failure message points at `await`, not at the real cause.
- **Cost if wrong:** a script relocated outside the package would not run; the renderer itself is unaffected.

**3. The late-payment overview cannot be rendered from a script that imports `paymentFollowUp.ts`**

- **Found during:** Task 2, while eyeballing the drawn overview.
- **Planned:** nothing says this; the plan treats the overview builder as a pure function, which it is.
- **Actual:** importing `paymentFollowUp.ts` pulls in `emailQueueWorker.ts`, which constructs a BullMQ worker and retries Redis forever. A throwaway probe wrote its PDF and then hung on `ECONNREFUSED 6379`.
- **Why:** the queue module starts work at import time. The unit tests tolerate it; a long-running script does not.
- **Cost if wrong:** a future ops script that wants the overview instead of the formal notice would hang in exactly this way. `formalNoticeSample.ts` deliberately imports only `pdfLetter.ts`, `formalNoticeText.ts` and the fixture, all of which are pure.

## Threat Mitigations

- **T-11.2-13 (path traversal):** the only filesystem inputs are this module's location, a fixed candidate list and an operator-set absolute path. No request value, tenant name or lease id reaches a path. `process.cwd` appears nowhere.
- **T-11.2-14 (silent corruption of non-Latin-1 names):** embedded font, central NFC, a no-Helvetica assertion, and extraction tests over five scripts.
- **T-11.2-15 (unbounded input):** the renderer streams to a Buffer of about 25 KB per letter; the sixty-row case was rendered and measured.
- **T-11.2-16 (content on stdout):** the renderer logs nothing. Its only error message carries paths. The sample script prints file paths and code point names, never letter content.
- **T-11.2-17 (final reminders failing in the worker):** fixed and proven twice over: the base64 attachment builds MIME through the real nodemailer after a JSON round trip, and the same test shows a round-tripped `Buffer` still throwing, which is why the producer may not queue one.

No new network endpoint, auth path or schema surface was introduced, so there are no threat flags.

## Document rendering

| Option | Description | Selected |
|--------|-------------|----------|
| Real PDF via a pure-JS library (pdfkit) | New dependency in apps/api, no browser, works under PM2 on m1, A4 and accents under our control | yes |
| PDF via the Playwright Chromium already in apps/api | No new dependency, but launches a browser in the API process on a shared box and needs a Chromium binary on m1 | |
| Print-ready HTML the landlord prints from the browser | Zero dependencies, but no fixed document for the court file and page breaks depend on the browser | |

**Auto-selected:** real PDF via a pure-JS library.
**Notes:** The existing `generateLatePaymentPdf()` returns plain text under `contentType: "application/pdf"`, so the final-reminder attachment is already wrong today and is fixed by the same renderer.

## Letter content

| Option | Description | Selected |
|--------|-------------|----------|
| Fixed sections, no statute citations, one optional free paragraph | Self-identifying as a formal notice, states facts, deadline and consequence; nothing the code could get legally wrong | yes |
| Fixed sections with statutory article references | Looks more authoritative, but Belgian obligations law was recodified into Book 5 of the Civil Code and a wrong cite in a generated legal document is worse than none | |
| Full per-owner template editor | Maximum flexibility, much larger scope, and a landlord can write an unenforceable threat | |

**Auto-selected:** fixed sections, no citations, one optional paragraph.
**Notes:** The consequence paragraph is limited to what a landlord may actually do: ask the justice of the peace to dissolve the lease. No lock changes, no re-letting, no self-help.

---

## Address data

| Option | Description | Selected |
|--------|-------------|----------|
| Landlord postal address on users, optional correspondence address on tenants, property address as the default addressee | Covers the case the feature exists for: the tenant is not at the rented property | yes |
| Property address only | No schema change, but unusable when the tenant has left or is detained, and leaves the sender block blank | |
| Free-text address typed per letter | Fastest to build, nothing is reusable, and every letter risks a typo in the sender block | |

**Auto-selected:** schema fields, with the property address as the fallback addressee.
**Notes:** Generation must fail with a clear message instead of producing a letter with a blank sender block. Schema change goes in with `db:push` because the Drizzle baseline snapshot is stale.

## Trigger and access

| Option | Description | Selected |
|--------|-------------|----------|
| New endpoint with the same authorisation as /send-reminder, button on the contract detail page | Consistent with the existing write path: property access, manager or higher, write scope for tokens, audit-logged | yes |
| Automatic generation at a fixed arrears threshold | Removes a decision the landlord must make deliberately; a formal notice is a legal step, not a cron job | |
| Settings-level bulk generation for all contracts in arrears | Useful later, but bulk legal letters without per-contract review is a bad default | |

**Auto-selected:** manual, per contract, same authorisation as a reminder.

---

## Logging and proof

| Option | Description | Selected |
|--------|-------------|----------|
| Log on generation, then mark as posted with date and registered-item reference | The deadline runs from the posting date and that is what a judge asks for | yes |
| Log on generation only | Simpler, but the record cannot prove when notice was given, which is the whole point of the letter | |
| No log, download only | Nothing to show in the arrears file | |

**Auto-selected:** log plus mark-as-posted.
**Notes:** Needs a new `formal_notice` value in the `communications.type` enum, which rides along with the address schema change.

---

## Arrears scope and money

| Option | Description | Selected |
|--------|-------------|----------|
| Every outstanding month on the contract, computed with the existing balance and interest code | One notice covers the whole debt, and the amount matches what the final reminder would state | yes |
| A single chosen month | Understates the debt and forces a second notice | |
| Landlord types the amount | Invites a mismatch between the letter and the ledger | |

**Auto-selected:** full outstanding balance from the existing computation. Interest and the late fee appear only where the contract provides for them.

---

## Language

| Option | Description | Selected |
|--------|-------------|----------|
| Letter templates per language in code, picked by the tenant's language | Follows the reminder-template pattern already in paymentFollowUp.ts | yes |
| Single English template | Unusable in a Belgian court file and against the four-language project rule | |
| Landlord's locale decides | The letter is addressed to the tenant, so the tenant's language is the right one | |

**Auto-selected:** per-language templates in code, keyed on the tenant's language. All four locales are mandatory; `i18n-completeness.test.ts` is the gate.

## Claude's Discretion

Every area above. `--auto` was used, so no user answered anything. The four decisions most worth review before planning: the new pdfkit dependency, the 15-day default deadline, including mark-as-posted in this phase, and one free paragraph instead of a template editor.

## Deferred Ideas

- Registered mail through a carrier API (bpost, eBox, registered e-mail).
- Per-owner editable letter templates in Settings.
- Judicial follow-on documents and an arrears-file deadline tracker.
- A "tenant unreachable" contract state, distinct from muted reminders.
